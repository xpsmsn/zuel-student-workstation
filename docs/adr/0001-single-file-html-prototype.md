# 产品本体是单文件 HTML 原型，桌面版只是薄外壳

全部界面与业务逻辑都在仓库根目录的 `中南大学生工作台.html` 一份文件里（约 8800 行、2.3 MB），没有框架、没有构建步骤，双击即可在浏览器打开。`app/` 里的 Tauri 工程只提供网页做不到的三件事（导出文件落盘、外链走系统浏览器、缩到系统托盘），并由 `.build/build-desktop.js` 把原型同步成 `app/src/index.html`（该产物不进库）。

这样做的理由是让「换成我们学校」对没有开发基础的老师成立：改校名、改校务系统地址、改表头映射，90% 只是改文字与网址，不需要理解框架，也不需要跑构建。代价是放弃模块化、类型检查与常规前端工程手段。

## Considered Options

v1.0 出包前对三条路线做过差异分析（见 `中南大学生工作台_方案说明.md` 附录 B）：

- **方案甲 · 原型直套外壳（已采用）**：界面完全不变、出可用软件最快；债留在以后
- **方案乙 · 按方案重写 Vue3**：组件化 + 类型安全、后续改功能最省力；但工期最长，**重写期间手里没有可用的软件**，且每页都要重新验收
- **方案丙 · 改用 Electron**：环境准备最快、不用装 Rust；但安装包约 120 MB、内存占用高，与「常驻轻量」的诉求相反，v0.1 已否决

方案乙的收益（组件化、TS 类型安全、现成的表格组件）在**功能稳定之后**才真正划算；真要做重构，先读附录 B，不要重新论证一遍。
