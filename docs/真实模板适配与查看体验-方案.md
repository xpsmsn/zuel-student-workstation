## 1. 三个真问题（数据实证，建议先修）

### 1.1 `住宿地址 = "-"` 被当成真值 —— **本批命中 2 行**

有 2 名学生（走读/不住校）的 `住宿地址` 就是一个 `-`，且 `宿舍楼/房间号/床位号` 三列全空。
后果：宿舍看板会出现一个**叫「-」的房间**、查寝打分表也会把这两个人当成该房间成员。

**改法**：在归一层引入「空值哨兵」——`-`、`—`、`–`、`/`、`无`、`暂无` 等统一归成空。
落点：`normalizeRow()` 里对值做一次 `sentinelToEmpty()`（列名归一之后、写库之前）。
**风险**：`-` 也可能是真实取值（例如某列合法值就是 `-`）。所以哨兵清单要保守，且**只清长度≤2 的全符号/占位值**，并在方案说明 §4.3 归一三原则里补一条。

### 1.2 只读第一张工作表，其余静默忽略 —— **已定：要支持选表**

`中南大学生工作台.html:7994`（学生导入）与 `:8382`（成绩导入）都是 `wb.Sheets[wb.SheetNames[0]]`。
本批文件的**第二张表 `Sheet1` 是一份 90 行的班委名册**（姓名 | 专业 | 职务，专业为「俄语」——不在主表专业列表里），当前完全读不到。
更危险的是另一半：如果某次导出的数据在第二张表，程序会**静默读到空表**而不报错。

**改法（已拍板：多表时让用户选）**：
- 读文件后，若有 **多于一张** 非空工作表 → 在导入向导里插入一步「选择工作表」，显示每张表的**名称 + 行数 + 前几列表头**，默认选第一张；
- 只有一张非空表 → 不打扰，行为与现在一致；
- **把选表逻辑抽成纯函数**（`sheetChoices(wb)` / 工作表名 → 行数组），这样能在测试沙盒里用假 `wb` 直接测；文件读取路径本身不进沙盒。

### 1.3 24 个新列涌入详情页 —— **已定：先只做「能看能编辑」**

42 列里 **18 列已认识**（4 列靠别名 + 14 列直接命中）、**24 列全新**。
但其中 **7 列全空**（电子信箱、考生号、出生地、国家地区、港澳台侨、培养层次、QQ号）、**4 列单值常量**（院系、学生类别、在籍状态、校区）——真正有信息量的约 **15 列**。

> 口径可复现：`python .build/read-xlsx.py <表> --check-aliases` 会逐列给出「别名命中 / 已认识 / 全新」。
> （本文件初稿曾写成"17 列已认识、25 列全新"——那是手数的，与工具实测不符，已按工具订正。）

**已拍板范围**：新列先只做到「详情页能看、能编辑、能被『列自定义』显示」，**不做**筛选 / 排序 / 看板 / 预设提级。

**改法**：扩 `FIELD_GROUPS`（详情页分组）与 `DEFAULT_COLS`/`SORT_COLS` 的可用列池，新增分组建议：

| 新分组 | 列 |
|---|---|
| 学籍与培养 | 学籍状态、是否在校、在籍状态、学生类别、培养层次、学制、现在年级、入学年月、预计毕业年份、预计毕业日期 |
| 户籍与家庭 | 入学前户口性质、户口所在地、家庭地址、家庭电话、籍贯、出生地 |
| 住宿（拆分形态） | 宿舍楼、房间号、床位号、校区 |
| 联系（补充） | 微信号、QQ号、管理老师 |
| 国际与身份 | 港澳台侨、国家地区 |

⚠️ 全空的 7 列**不要**因为「分组里有它」就凭空出现在详情页——沿用现有规则：整批为空 → 不显示（`isHiddenField` / `fieldHasData` 已具备该能力，落点要确认接上）。

## 2. 看板预设项（每条都标了本批真实命中）

### 2.1 建议新增（按价值排序）

| 预设 | 判定式 | 本批命中 | 依赖字段 |
|---|---|---|---|
| **学籍异常** | `学籍状态 ≠ 在读` **或** `是否在校 = 否` | **2** | 学籍状态、是否在校 |
| **不住校（无床位）** | `宿舍` 为空 | **2** | 宿舍 |
| **不在校却有床位** | `是否在校 = 否` **且** `宿舍` 非空 | **1** | 是否在校、宿舍 |
| **第二学士学位** | `学制 = 2` 或 `班级` 含「二」 | **25** | 学制 / 班级 |
| **缺联系方式** | `手机号/联系电话` 都为空 | **25** | 联系电话 |
| **无证件号** | `身份证件号` 为空 | **25** | 证件号码 |
| **毕业年份 / 提前毕业** | `预计毕业年份` ≤ 今年+1 | 2028×188、**2027×1** | 预计毕业年份 |
| **户口性质（农业/非农）** | `入学前户口性质` 取值 | 农业 80 / 非农 84 | 入学前户口性质 |
| **缺微信号** | `微信号` 为空 | **86** | 微信号 |

已有的 `班委成员` 不用改：真实模板的列名是**「职务」**，而别名表 v1.9.2 已经把 `职务 → 班委`（`:3827`），本批 83 人可正常筛出。

### 2.2 建议**不**做（以及为什么）

| 不做 | 原因 |
|---|---|
| 港澳台侨 / 国家地区 | 本批**全空**。做了也会被 `presetAvailable` 置灰，先不占位 |
| 校区 / 学生类别 / 在籍状态 / 院系 | **单值常量**（本批分别只有 1 个取值）→ 命中=全部人，等于没筛 |
| 「只看我的学生」（管理老师） | **不适合做预设**：判定式需要知道「我是谁」，而程序没有当前辅导员的概念。更适合做成**筛选字段**（加进 `FILTER_FIELDS`）。真实取值只有 2 种：`吴章凡(辅导员)`×179、`吴章凡(辅导员),周怡(辅导员)`×10 —— 注意第二列是**逗号分隔的多人**，要做子串匹配（同「关注标签」的手法） |

### 2.3 顺带发现一个机制缺口

`presetAvailable()`（`:3904`）只判「依赖字段**整列全空**」→ 置灰；
但**判不出「单值常量列」** → 常量列上的预设会显示"可用"，点进去却是全部学生。
建议：`need` 的判定从「有非空值」升级为「**至少 2 个不同取值**」，并在置灰提示里区分这两种情况（"本批未包含该字段" vs "本批该字段只有一种取值"）。

## 3. 交互动画与查看体验

### 3.1 现状盘点（原型全文实测）

| 项 | 数量 |
|---|---|
| `transition:` | **52** 处（多为 .12s–.22s 的 hover/焦点反馈，健康） |
| `@keyframes` / `animation:` | **7 / 8** 处：`barUp`(柱状 .55s)、`donutIn`(环形 .7s)、`hbarIn`(横条 .6~.7s)、`ddIn`(.14s)、`quoteIn`(金句 .42s)、`settle`/`bedPop`(拖拽落位，事件驱动，正确) |
| `innerHTML =` | **54** 处（`renderMain`、`renderDashBody`、`renderDashMetrics`、`renderRows` 是入口） |
| `prefers-reduced-motion` | **0** —— 系统开了「减少动态效果」也照样动（无障碍缺口） |
| `will-change` / `scroll-behavior` / `requestAnimationFrame` | 0 / 0 / 0 |
| `setInterval` | 2（金句轮换等） |

### 3.2 核心诊断：**入场动画挂在「每次重建」的区域上 → 每次筛选/搜索都重播一遍**

`.bar`、`.donut-seg`、`.hbar`、`.quote-bar` 都在 `renderDashBody()` / `renderMain()` 生成的那段 HTML 里（`:635`、`:645`、`:665`、`:164`）。
而这些函数是**整段替换 innerHTML**（`renderDashBody` 的注释自己写着"独立渲染，便于筛选时局部刷新"）。
于是：**改一个筛选条件 → 柱状图再"长"一次、环形再"转"一次**。这是"闪/跳"的最可能来源，也解释了为什么你对跳变敏感（v2.1.0 修过"金句框忽长忽短"）。

补充一处**已核实**的具体项：金句 `.quote-text` 挂着 `.42s` 的 `quoteIn`（opacity + 位移 + blur），而 `renderQuote(true)` 里用了**强制 reflow 重放动画**的手法（`:4145-4147`：`animation='none'` → `void offsetWidth` → `animation=''`）；轮换由 `setInterval` 驱动，默认 **5 秒**一次（`quoteIntervalMs()`，设置里可改 3–120s，**鼠标悬停会暂停**）。
所以「每 5 秒滑入一次」是**刻意做出来的**，好处是换句能被注意到。它算不算问题属于**偏好**，不是缺陷——可选：把默认间隔调长 / 轮换时只做轻微 opacity / 完整滑入只留给手动点击。

### 3.3 候选改法（按「改动大小 / 收益」排，待你挑）

| # | 改法 | 收益 | 代价 |
|---|---|---|---|
| A | **加 `prefers-reduced-motion` 兜底**：该媒体查询命中时把所有 `animation`/`transition` 时长归零 | 无障碍；对晕动症用户是硬需求 | 极小（一段 CSS） |
| B | **入场动画只播一次**：首次进入该视图才播；之后的重建沿用「不再播」。落地方式：在应用根节点（或 `#dashBody`）上打一个类（如 `.no-entrance-anim`），CSS 里一行覆盖 `animation:none` —— 不必改每个渲染函数 | 直接消除"每次筛选都长一次" | 小；需要一处状态位 |
| C | **金句轮换的动画分级**：轮换时只做轻微 `opacity`，完整滑入只留给手动点击（或把默认 5s 间隔调长） | 去掉每 5 秒一次的打扰，同时保留"换句能被察觉" | 极小；**属偏好取舍，需你定** |
| D | **缩短/去掉阶梯延迟**：`animation-delay:var(--delay)` 在 20+ 根柱子上会拉出"依次长出"的长尾 | 视觉更利落 | 极小 |
| E | **筛选时局部刷新**（只更新变化的那块，而不是整段 innerHTML 重建） | 根治闪烁；代码库已有此方向（`renderDashMetrics` 的注释） | **大**，需重构渲染路径，建议单独排期 |
| F | **列表切换加一次 120ms 淡入**，替代硬跳 | 查看体验更连贯 | 小；注意别与 B 冲突 |

### 3.4 查看体验的其它具体项（与 1.3 配套）

1. **详情页分组扩容**（见 1.3 表）——否则 14 个有信息量的新列只能以"其他字段/自定义字段"堆在末尾。
2. **列表列池**：`DEFAULT_COLS`（`:5353`）目前 10 列；建议把「学籍状态」这类**一眼判断状态**的列放进可选池靠前位置（不默认显示，避免列表变挤）。
3. **筛选字段池**：`FILTER_FIELDS`（`:3869`）12 项 → 增补 `管理老师`、`学籍状态`、`是否在校`、`户口性质`、`校区`（本批常量，但对别的批次有意义）。
4. **导入确认页的三态提示**已有（已识别/保留/新字段/全空列）。本批会产生 **24 个"新字段"** —— 建议在新字段较多时给一句总结（"本次有 24 列未识别，将原样入库"），否则辅导员会逐个看过去。**待拍板**。
