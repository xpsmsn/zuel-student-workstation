所以「真实截图」和「axe 自动扫描」需要人在浏览器里跑一次。可直接粘贴到 DevTools Console：

```js
// 1) 焦点环是否真的画出来：自动聚焦每个可聚焦元素并读 outline
[...document.querySelectorAll("input,select,textarea,button,a[href],[tabindex]")].forEach((el,i)=>{
  el.focus({focusVisible:true});
  const cs=getComputedStyle(el);
  if(cs.outlineStyle==="none"||parseFloat(cs.outlineWidth)<2) console.warn("焦点不可见 #"+i, el, cs.outlineStyle, cs.outlineWidth);
});
console.log("焦点检查完成：没有 warn 即全部可见");
```

## ④ 本轮明确没做的事（避免误解）

1. **键盘仍然到不了核心交互**：侧栏项、表格行、统计卡还是 `div + onclick`，没有 `tabindex`/`role`，
   焦点环只对本来就可聚焦的元素（输入框、按钮、链接、select）生效。P0-① 属第二轮 DOM 语义化。
2. **撤销条 / confirm / toast 仍无 `role` / `aria-live` / 焦点陷阱**（P0-④，第二轮）。
3. 触控目标尺寸、hover-only 提示、图表文本等价物、顶栏 ⋯ 菜单分组等 P1 项均未动。

## ⑤ 复现方式

本文件 ①② 的所有数字由 `.verify/spec-check.mjs` 生成，可随时重跑：

```powershell
node .verify/spec-check.mjs   # 输出聚焦规则特异性对比 + 三主题对比度
```

脚本做两件事：从 `index-round1.html` 里抠出所有 `<style>` 块，算出「带 `outline:none` 的规则」
与 `round1-a11y` 新规则的选择器特异性并逐一比较；再按 `#ffffff / #373c3f / #eaefdd` 等实际背景
重算每个文字令牌的 WCAG 对比度。
