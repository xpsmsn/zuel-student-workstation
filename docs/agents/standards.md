# 本仓库的编码与维护标准

> 这份文件收录**仓库里已经写明的**规则，每条都标了出处；它不发明新规则。
> 例外只有一处：**§七末尾「测试必须走真实入口路径」是 v2.1.x 三次实证踩坑的结论，已在那一节标明出处**。
> 用途：给 `code-review` 的 Standards 轴当依据（见 `docs/agents/domain.md`）。
> 分两类：**编码 / 维护规则**（直接判 diff 对错）与**领域不变量**（违反了就是缺陷）。
> 术语一律以 `CONTEXT.md` 为准；刻意为之的设计见 `docs/adr/`。

## 一、文件角色（README.md「目录」表）

- `中南大学生工作台.html` —— **产品本体的唯一真源**。改产品逻辑 / 界面，改这里。
- `app/src/index.html` —— **自动生成**（由 `.build/build-desktop.js` 从原型同步），
  每次出包都会被覆盖。**永远不要直接改它**；改完原型必须重新生成它。
- `app/` 是 Tauri 桌面外壳；`.build/` 放构建、回归测试、出包脚本；`发布/` 放安装说明。

## 二、绝不能改的三处（README「⚠️ 三个地方千万别乱动」）

| 东西 | 为什么 |
|---|---|
| Tauri `identifier`（`cn.edu.zuel.studentworkstation`） | 它决定数据存在电脑的哪个文件夹。**已部署后再改 = 所有人数据"找不到"，等同于丢失**；新学校要在一开始就换成自己的，之后永不再动 |
| 存储键 `counselor_workstation_v2` | 同上，是数据在浏览器里的名字 |
| `app/src/index.html` | 自动生成，改了会被覆盖 |

配套（方案说明 附录 A36）：**凡涉及标识符的改动，都必须有一条断言盯着。**

## 三、版本号与发布命名（README「开发者说明」）

- **版本号唯一来源** = `app/src-tauri/tauri.conf.json` 的 `version`，脚本自动读取，**不手写**。
  改版本时 `app/package.json` / `Cargo.toml` / `Cargo.lock` 要同步
  （v1.9.8 曾漏掉 `app/package.json`，属于已发生过的疏忽）。
- **发布命名规则（长期遵守，别再换写法）**
  - 给人看：`中南大学生工作台-v<版本>-<用途>.<扩展名>`（用途 = 绿色版 / 安装程序 / 单位部署）
  - GitHub 附件：`ZUEL-StudentWorkstation-v<版本>-Portable.exe`
    （英文名 —— 中文名会被 GitHub 清成 `-.exe`）

## 四、领域不变量（方案说明 §4.2 / §4.3 / §4.4 / §4.6）

**四条铁律**：①备注永不覆盖 ②空值不覆盖 ③本次表未出现的列原样保留 ④不静默删除 + 可回溯
（异常行单独列出、导入记增改计数。「覆盖当前批次」是用户显式授权的例外：二次确认 + 删前自动备份。）

**归一四原则**：①只做「读入时归一」，**不改写原始表** ②别名可扩展（加表行，不改导入代码）
③同行多别名冲突：优先取非空值；都非空则取本表靠前的那个 ④**占位符一律当空（空值哨兵）**：
整串由占位符号组成（`-` `—` `/` …）或命中占位词（`无` `暂无` `N/A` `null` `none`…）→ 清成空；
这是**只清不填**，方向安全（空值本就不覆盖旧值）。⚠️ 该判定在 JS 与 `.build/read-xlsx.py`
各有一份实现，靠那个脚本的 `--selftest` 核对一致性。

**引用不变量**：`S.students` 必须**始终指向当前批次的 `students` 数组（同一引用）**，
写入口唯一 = `setStudents(arr)`；成绩层同理 = `setGrades(arr)`。
任何 `S.students = [...]` / `S.grades = [...]` 直接赋值都会让顶层引用与批次脱钩
（界面看着对、一刷新就回滚）；`save()` 内置开发期断言自查。

**成绩语义**：无成绩记录返回 `null`，界面显示「暂无成绩」，**绝不显示 0**。

## 五、桌面版环境约束（方案说明 附录 A34）

**桌面版（WebView）里不要用系统弹窗**：`prompt()` / `confirm()` 会被吞掉，用户会以为功能坏了。
自定义值输入改**页面内联输入框**，重命名改行内编辑。回归里有静态断言守「源码内无 `prompt(`」。

### 测试必须走真实入口路径（v2.1.x 实证补充）

> 本节**不是**从别处抄来的规则，而是三次实际踩坑的结论。共同症状都是
> **「保护看着在那儿，其实没盖住那条路」**：

| 实例 | 没盖住什么 |
|---|---|
| 导入合并的铁律③ | 同一段逻辑有两份复制体，一份有铁律③、一份没有；测试只走了其中一条 |
| 「新建批次」取消勾选失效 | 注释自称覆盖三条模式路径，实际只覆盖两条；测试直调 `doImportMerge`，**结构性看不见** `doImport` 的 `new` 分支 |
| `verify-v198.js` 自称「四项真机核对」 | 实际只有两项有断言，另两项只 `console.log` |

**三条规则**：

1. **测试要走使用者点下去时的那条真实路径**，不要为了省事直调内层函数。
   写之前问一句：「我这个调用，和用户点下去走的是同一条路吗？」
2. **一条规则只允许一份实现**。多条路径需要同一规则时，抽成函数、**各入口各调一次**
   （见 `mergeRowInto()` 与 `filterSkippedCols()`），并用静态断言守住**调用点数量** ——
   少一处就是这类 bug。
3. **自称「N 项核对」的脚本，要么 N 项都有断言，要么改掉那句自称。**
   把值 `console.log` 出来不算核对。
